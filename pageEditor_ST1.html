Home Page

Technical Description

HTML Technical Description

  • <header> and <nav> handle the primary site navigation and branding logo
  • .nav-links contains anchor tags for multi-page navigation
  • .scene_bg uses an onerror attribute to hide the hero image if the file fails to load
  • .hero-content serves as the landing introduction with CTA buttons
  • .dashboard-container implements a horizontal scroll layout using overflow-x: auto
  • .card.peek components use nested structures for interactive hover expansion
  • :root variables define a centralized color palette and typography
  • @keyframes bounce powers the scroll indicator's vertical animation
  • backdrop-filter creates a modern glassmorphism effect on the navigation bar

CSS Technical Description

  • *, *::before, and *::after use box-sizing: border-box to simplify layout calculations
  • .scene_bg uses position: fixed and inset: 0 to create a static, full-screen background layer
  • :root defines CSS variables for --teal, --font-body, and --nav-bg for global consistency
  • backdrop-filter: blur(14px) is applied to the <nav> for a glassmorphism design effect
  • .logo-circle uses a radial-gradient to generate a custom-styled brand icon
  • .btn-fill and .btn-outline use transition and transform for smooth hover interactions
  • @keyframes bounce creates the vertical animation for the .scroll-indicator element
  • .dashboard-container uses display: flex and scroll-snap-type: x mandatory for a horizontal gallery
  • .card.peek:hover triggers a width expansion from 85px to 220px to reveal hidden content
  • .peek-overlay uses transform: rotate(-90deg) to display text vertically on unexpanded cards

Accessibility

  • lang="en" on the <html> tag ensures screen readers use correct pronunciation
  • <header>, <nav>, <main>, and <footer> act as semantic landmarks
  • alt attributes on all images provide descriptive text for visually impaired users
  • class="active" provides a clear structural indicator of the user's current location
  • <h1> through <h3> tags establish a clear heading hierarchy
  • display=swap on Google Fonts prevents invisible text during font loading
  • pointer-events: none on overlays ensures they don't block link interactions
  • transform and opacity changes provide non-color feedback for interaction
  • meta name="viewport" ensures the site is responsive and zoomable on mobile
  • color: var(--white) ensures high contrast readability against the dark ocean-themed background
  • .nav-links a:hover uses background: var(--white-10) to provide a clear visual focus state
  • .nav-links a.active uses background: var(--white-20) for structural location identification
  • letter-spacing on uppercase text improves readability for users with visual processing needs
  • .scroll-indicator uses motion as a non-text cue to signal that more content is available below
  • scrollbar-width: none hides the scrollbar while overflow-x: auto maintains keyboard scrolling
  • transition: opacity 0.4s ease prevents jarring visual changes when expanding content cards
  • pointer-events: none on .peek-overlay prevents decorative text from blocking mouse clicks
  • font-family: var(--font-body) defaults to sans-serif for maximum character legibility

Gallery Page

Technical Description

HTML Technical Description

  • <header>, <nav>, <main>, <section>, and <footer> handle the primary semantic landmarks for improved SEO and document structure
  • Google Fonts (Cinzel, Playfair Display, JetBrains Mono) are imported to create a specific atmospheric hierarchy for typography
  • .scene_bg uses an onerror attribute to hide the hero background if the image asset fails to load
  • .nav-links contains anchor tags and an .active class to handle multi-page navigation and current location highlighting
  • .hero-content (pageup) serves as the landing introduction using <span>, <h1>, and <p> to establish the narrative
  • .dashboard-container implements a gallery grid housing .card components with images, headings, and descriptions
  • #galleryModal serves as an interactive hidden div with customization buttons for user-end font and color schemes
  • <footer> contains project metadata, developer details, and accessibility links.

CSS Technical Description

  • :root stores global design tokens like --teal, --card-bg, and typography variables.
  • *::before, *::after ensures a consistent CSS box model and resets default browser margins.
  • .dashboard-container uses grid-template-columns to manage the responsive 3-column layout.
  • .card-image utilizes object-fit: cover to maintain image aspect ratios within fixed containers.
  • @media (max-width: 768px) triggers the mobile-friendly single-column view.
  • .alt-font-active and .alt-color-active provide the logic for user-driven theme overrides.

JavaScript Technical Description

  • cards is a NodeList used to attach event listeners to every gallery item.
  • mouseenter and mouseleave events handle the dynamic "lift" and border-color animations.
  • imgSource and altText are variables used to capture data from a clicked card for the modal.
  • modal.style.display toggles the visibility of the expanded view between flex and none.
  • classList.toggle is used to apply or remove accessibility themes on the modalTarget.
  • window.addEventListener('click') allows users to close the modal by clicking outside the content box.

Accessibility

  • <html lang="en"> defines the base language to ensure screen readers use correct pronunciation.
  • <main> and <nav> provide ARIA landmarks, allowing users to jump directly to specific sections.
  • aria-label="Back to top" provides a clear text description for the symbolic "↑" link for non-visual users.
  • <header> and <footer> group related navigation and metadata for a logical page hierarchy.
  • alt attributes on all images (e.g., "Discarded fishing net") provide critical visual context to screen reader users.
  • opacity: 0.55 on the background image maintains a high contrast ratio between the text and the scenery.
  • line-height: 1.6 in the modal text prevents crowding, making long descriptions easier for users with cognitive impairments to read.
  • cursor: pointer and :hover states give immediate visual feedback that an element is interactive.
  • btnFont toggles a monospaced font, which is often easier for users with dyslexia or reading difficulties to process.
  • btnColor switches to a high-contrast scheme, assisting users with color blindness or light sensitivity.
  • overflow-y: auto ensures that the modal remains fully scrollable for users on small screens or with high browser zoom.
  • onerror="this.style.display='none'" hides broken images to prevent screen reader confusion and maintain a clean layout.

Content Page

Technical Description

HTML Technical Description

  • The shared content page template was collaboratively created by Nethnu Bulathsinghala and Kulith Silva.
  • The technical description and accessibility are consistent and shared across the entire team.
  • <!DOCTYPE html> and <html lang="en"> define the document as HTML5 and set the language for accessibility and correct interpretation.
  • <meta charset="UTF-8"> ensures support for a wide range of characters and symbols.
  • <meta name="viewport"> enables responsive design by matching the layout to the device width.
  • <link rel="stylesheet"> imports external CSS files and Google Fonts to style the page.
  • <header> and <nav> structure the navigation bar, improving usability and accessibility.
  • id="quickJump" acts as a navigation landmark with an aria-label to ensure screen readers identify it as a functional section for jumping between content.
  • id="qjPill" serves as the main container for the navigation items, likely styled as a floating or sticky horizontal "pill" bar.
  • class="qj-item" creates internal page links using href anchors (like #act1) to scroll the user to specific sections without a page reload.
  • class="active" and aria-current="true" are used on the first link to visually and programmatically mark the user's starting location in the document.
  • class="qj-connector" provides a structural element used in CSS to draw connecting lines between the navigation points, creating a "progress tracker" look.
  • class="qj-dot" functions as a decorative or functional bullet point within each link to give the menu a modern, minimalist aesthetic.
  • data-target attributes store the ID of the destination section, which is typically used by a JavaScript scroll-spy to highlight the correct link as the user scrolls.
  • <main> wraps the primary content, helping screen readers identify the main section of the page.
  • <section> elements divide the page into logical content areas such as hero, content cards, and handoff.
  • id attributes (e.g., #top, #act3) are used for internal navigation and anchor linking.
  • class attributes are used to apply consistent styling and layout through CSS.
  • data-* attributes (e.g., data-bg, data-ch) store custom data used by JavaScript for dynamic behaviour.
  • <img> elements include alt text for accessibility and onerror to hide images if they fail to load.
  • aria-hidden="true" is used to hide decorative elements from screen readers.
  • <a> elements provide navigation between pages and within the page using anchor links.
  • <script src="..."> links an external JavaScript file, separating behaviour from structure.
  • <footer> contains additional navigation and student details, placed at the end of the page.

CSS Technical Description

  • body sets a dark background colour, creating the base theme of the page.
  • .sonar uses position: absolute, border-radius: 50%, and transform to create circular ripple elements.
  • @keyframes sonarRing defines the ripple animation using transform and opacity to simulate expanding waves.
  • .sonar.fire, .fire2, and .fire3 apply staggered animations using delays for a layered ripple effect.
  • #sonarpart uses position: fixed and pointer-events: none so the animation stays centred and does not block user interaction.
  • .bg uses position: fixed and opacity transitions to create smooth background image changes.
  • .bg.active switches visibility by increasing opacity and z-index, controlling which background is shown.
  • .bimg uses object-fit: cover to ensure images fill the screen without distortion.
  • .bg::after applies gradient overlays using pseudo-elements to improve text readability over images.
  • .chapters uses Flexbox (display: flex) to centre content both vertically and horizontally.
  • clamp() is used for responsive font sizes, adjusting text smoothly across different screen sizes.
  • .contentcon uses backdrop-filter: blur() and semi-transparent backgrounds to create a glassmorphism effect.
  • .contentcon.visible uses opacity and transform transitions to animate content appearing on scroll.
  • z-index is used throughout (e.g., background = 0, content = 10) to control layering of elements correctly.
  • @keyframes scrollDrop animates the scroll indicator line using transform and opacity for a looping effect.
  • #quickJump is fixed to the right side of the viewport, vertically centered using transform: translateY(-50%)
  • #qjPill is the container, a frosted glass pill using backdrop-filter: blur, dark semi-transparent background, and a subtle sky-blue border
  • .qj-item is each nav dot row, flexbox-aligned, with a soft hover background highlight
  • .qj-label is a tooltip that appears to the left of each dot, hidden by default (opacity: 0, transparent color), revealed on hover, focus, or when .active
  • .qj-dot is the circular indicator, small 6px dot with a sky-blue tint; scales up on hover and glows on active
  • .qj-item.active .qj-dot applies a cyan glow via box-shadow and scales the dot to 1.4x
  • .qj-dot::after creates a pulse ring, an expanding border that animates outward using @keyframes qjPulse only when the item is active
  • .qj-connector is a thin 1px vertical line between dots, acting as a visual divider

JavaScript Technical Description

  • document.getElementById() is used to select specific elements such as the scroll bar and sonar rings.
  • document.querySelectorAll() selects multiple elements (e.g., sections with data-bg) and converts them into an array using Array.from().
  • reduce() is used to create an object mapping background IDs to their corresponding DOM elements for efficient access.
  • switchBg() function controls background transitions by adding and removing the active class.
  • classList.add() and classList.remove() dynamically update CSS classes to change styles and trigger animations.
  • setTimeout() is used to delay actions such as resetting z-index and controlling animation timing.
  • window.addEventListener('scroll') listens for scrolling to update the progress bar and trigger effects.
  • window.pageYOffset and document height calculations are used to determine scroll progress.
  • getBoundingClientRect() calculates the position of sections to detect which section is closest to the viewport centre.
  • dataset (e.g., dataset.bg) accesses custom HTML data attributes to control background switching.
  • IntersectionObserver detects when elements enter the viewport and adds a visible class for animations.
  • addEventListener('load') ensures initial functions run only after the page fully loads.
  • Tracks which section is closest to 45% down the viewport
  • qjItems = all nav links in #quickJump; qjTargets = their data-target section IDs
  • On each call, computes a midpoint (winMid) at 45% of the viewport
  • Loops through all target sections, finds the one whose center is closest to winMid
  • Toggles the active class on the matching nav item, removes it from the rest
  • scrollY is passed in by the caller, usually from a scroll event

Accessibility

  • lang="en" defines the page language, helping screen readers use correct pronunciation.
  • alt attributes on images provide descriptions for visually impaired users.
  • aria-hidden="true" hides decorative elements (e.g., background images, sonar effects) from screen readers.
  • <header>, <nav>, <main>, <section>, and <footer> create a semantic structure for easier navigation.
  • aria-label (e.g., "Back to top") gives meaningful descriptions to icons or non-text elements.
  • <a> links enable keyboard navigation between sections and pages.
  • <em> and <strong> provide semantic emphasis, improving how screen readers interpret content.
  • id attributes allow users to jump to sections using anchor links, supporting keyboard navigation.

Challenges and Lessons Learned

  • Synchronizing the back to top anchor link with smooth scroll behavior required careful CSS to HTML coordination for a seamless user transition.
  • I learned that consistent CSS naming conventions for components like card and btn custom are essential for building a scalable and maintainable codebase.
  • Designing the dashboard container grid to remain fluid across various screen sizes while maintaining a balanced visual hierarchy was a significant layout challenge.
  • Managing the stacking order of the scene bg image and the header navigation was a challenge that required precise z index management in the CSS.
  • Implementing custom controls inside the modal taught me how to toggle global CSS variables to change font styles and color schemes dynamically.

Compliance

  • <!DOCTYPE html> and lang="en" are included on both pages, ensuring proper HTML5 structure and correct interpretation by browsers and screen readers.
  • W3C HTML Validator was used to check both pages for structural errors, missing tags, and incorrect nesting before submission.
  • W3C CSS Validator was used to validate style.css, feedback.css, and team.css, ensuring no invalid properties or syntax errors.
  • alt attributes are applied to all images, and semantic HTML elements are used for buttons, links, and inputs to meet accessibility standards.
  • Google Gemini was used to generate images, and Google Fonts are loaded via their official API under an open licence, avoiding copyright issues.
  • HTTPS is used for all external resources, ensuring secure loading and preventing mixed content warnings.
  • No data storage is implemented in the feedback form, aligning with data minimisation principles as no user input is saved or transmitted.
  • novalidate ensures all validation is handled client-side with JavaScript, meaning no data is sent to external systems.
  • Appropriate content is maintained across both pages, with no offensive or misleading material, complying with acceptable use standards.
  • Responsive design is implemented using flex-wrap: wrap on the team page and max-width with margin: auto on the feedback page to ensure usability across devices.
