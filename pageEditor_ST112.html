🌊 Splash Screen

Overview

The Splash Screen serves as the first point of contact between the user and the website. Its purpose is to introduce the site's theme — oceanic depth, SDG 14, and the team behind the project — while creating a moment of atmospheric immersion before the Home Page is loaded.

HTML Structure

The page is structured around a single full-viewport <section class="hero"> element containing all layers. A layered visual hierarchy is achieved through stacking absolutely-positioned elements inside this section: a <img class="hero-bg"> night ocean image, animated star and bioluminescence layers (<div id="stars">), a <div class="moonHalo">, the moon itself, and ripple rings (<div id="ripples">). The content panel uses <div class="heroContent"> to group the title, countdown and skip button. An <div class="info-panel"> holds the team members and SDG mission statement. Semantic elements such as <p> and <h1> with <em> are used to establish heading hierarchy and emphasis.

CSS Techniques

The visual richness of the Splash Screen is delivered almost entirely through CSS. Key techniques include:

  • CSS custom properties (variables) — used on individual star and ripple elements to pass randomly generated durations, delays, sizes, and colours from JavaScript into the CSS animation engine via --rdur, --rdelay, --duration, --delay, --op and --bio properties.
  • @keyframes rippleOut — animates concentric ring elements from scale(0) to scale(3) while fading opacity, creating expanding water ripples on the moonlit surface.
  • @keyframes twinkle and @keyframes bioTwinkle — produce independent pulsing effects for white star dots and teal bioluminescent dots. The bioTwinkle variant has an asymmetric easing to mimic organic luminescence.
  • Depth bands — two semi-transparent horizontal stripes with position: absolute and background: linear-gradient label the Sunlight and Twilight ocean zones, reinforcing the educational depth narrative.
  • CSS loader ring — a rotating dashed ring (.loader-ring) with an orbiting dot (.loader-dot) signals loading state using a CSS animation rather than any image or GIF.
  • Layering with z-index — each visual layer (background, stars, moon, ripples, content) is assigned a distinct z-index so they composite correctly without JavaScript.

JavaScript Functionality

A linked external script (scripts/splash.js) handles three runtime concerns:

  • Star and ripple generation — loops that programmatically create <div class="star">, <div class="bio-dot"> and <div class="ripple"> elements with randomised CSS custom property values before injecting them into the DOM. This keeps the HTML clean while producing hundreds of unique animated particles.
  • Countdown timer — a setInterval decrements the value displayed inside <span id="countNum"> each second, providing the "Entering site in 4…3…2…1" experience required by the coursework brief.
  • Auto-redirect — the HTML <meta http-equiv="refresh"> tag handles the 4-second redirect to home.html as specified in the brief. The skip button calls skipIntro() which navigates immediately using window.location.href.

Accessibility

All images carry descriptive alt text (e.g. "Night ocean scene with clouds and stars"; "Full moon rising over the ocean"). The skip button is a native <button> element and is therefore keyboard-focusable by default. Heading hierarchy begins at <h1> with a meaningful page title. Depth-band labels use <span class="depth-label"> inside each band so screen readers can convey the zone information.

⚡ Action Impact Simulator

Overview

The Action Impact Simulator (AIS) is an interactive page that invites users to select real-world actions they can take to protect ocean health, and shows them how their collective choices move the needle on SDG 14. It is the most technically complex page in my assignment, combining embedded CSS, DOM manipulation, dynamic background switching, and animated feedback components.

HTML Structure

The page uses the shared team template (header, <main>, footer) extended with page-specific sections:

  • .page-hero — a visually distinct banner using <section> containing the page title and an italic serif subtitle. This sits above the content container and establishes context.
  • .feed — a glass-morphism panel acting as the live score dashboard. It uses a CSS grid (grid-template-columns: auto 1fr) to split the numeric score from the descriptive feedback. Child elements include <div id="score">, <div id="level">, <p id="message">, and the <div id="oceanState"> status box.
  • .actiongrid — a CSS Grid container holding six .card elements, one per ocean action. Each card includes a <img> thumbnail, category label, title, description, and an impact-points badge. Cards carry role="checkbox" and an onclick handler for accessibility and interaction.
  • A fixed-position <img id="sceneBg"> background image sits behind all content and is swapped by JavaScript at each impact threshold.

CSS Techniques (Embedded)

All page-specific styles are declared inside a <style> block in the <head> and do not override the global style.css. Techniques include:

  • Glass-morphism feed panel — achieved with background: rgba(3,13,26,0.85) combined with backdrop-filter: blur(28px) and a semi-transparent border to create the frosted-glass appearance.
  • Dynamic colour theming via modifier classes — the .feed panel and .score number each have three modifier classes (.impact-low, .impact-mid, .impact-high) that change border colours and text-shadow tones. JavaScript adds/removes these classes, keeping all visual expression in CSS.
  • @keyframes scorePop — a micro-animation that scales the score number briefly on change, reinforcing the moment of user interaction.
  • @keyframes badgePulse and @keyframes cardEntry — the impact badge pulses when the level changes, and cards stagger into view on page load using animation-delay increments.
  • Progress bar — .bart is a container with overflow: hidden; the inner .barF fill uses a three-stop linear-gradient from red through amber to green and its width is animated with transition: width 0.7s cubic-bezier. Two pseudo-elements (::before / ::after) mark the Low/Medium and Medium/High thresholds as hairline dividers.
  • Action card grid — display: grid; grid-template-columns: repeat(auto-fill, minmax(260px, 1fr)) makes the card grid responsive across screen sizes without media queries.
  • Selected card state — .card.selected applies a coloured border, box-shadow glow, and reveals the .tick checkmark using opacity and transform transitions.

JavaScript Functionality

The AIS logic lives in scripts/ais.js. Key functions include:

  • toggle(id, event) — toggles the .selected class on the clicked card, updates the selected Set tracking which cards are active, and calls updateFeed().
  • updateFeed() — sums impact points from selected cards, updates the score display with a scorePop animation, updates the progress bar width (capped at 100%), determines the impact level (Low: 0–4 pts, Medium: 5–10 pts, High: 11–17 pts), applies the correct modifier class to the feed panel and score, and calls updateBackground().
  • updateBackground(level) — fades the background image to opacity: 0, swaps the src attribute to the correct asset (assets/bg_low.png, assets/bg_mid.png, assets/bg_high.png), then fades back to full opacity. This gives a smooth crossfade controlled entirely by JavaScript — not CSS transitions on the class alone.
  • resetall() — clears the selected Set, removes .selected from all cards, and resets the feed panel to its initial neutral state.
Impact thresholds: Low = 0–4 pts  ·  Medium = 5–10 pts  ·  High = 11–17 pts (max possible score: 17 pts across all 6 cards).

Accessibility

Each .card uses role="checkbox" so screen readers announce the interactive nature of the element. The action grid container uses role="group". All card images include descriptive alt text relevant to the action (e.g. "Volunteers cleaning a beach"). The background image carries an alt describing its dynamic purpose ("Ocean state background — changes based on your impact score"). The <main> landmark and semantic <h1> / <h3> hierarchy support navigation by heading.

📖 Content Page — ST2

Overview

My individual content page explores the threats facing ocean ecosystems in relation to SDG 14: Life Below Water. The page covers plastic pollution, overfishing, ocean acidification, and coral reef degradation, presenting each topic across clearly defined sections with supporting images and internal navigation.

HTML Structure

The page uses the shared team template with the following content-specific additions:

  • A sticky internal navigation <nav class="internal-nav"> at the top of <main> linking to each section via href="#section-id" anchor references.
  • Four clearly labelled <section> elements, each with a unique id attribute, a <h2> heading, supporting <p> paragraphs, and at least one contextual image.
  • A <a href="#top" class="go-top"> button fixed to the bottom-right of the viewport using position: fixed, implemented purely in HTML and CSS without JavaScript.
  • Proper heading hierarchy: one <h1> page title followed by <h2> section headings and <h3> sub-headings where further structure is needed.

CSS Techniques

Page-specific styles are included as embedded CSS within a <style> block and cover:

  • position: sticky; top: 80px on the internal navigation bar so it follows the user while scrolling without overlapping the global header.
  • Responsive image styling with max-width: 100%, border-radius, and subtle box-shadow to maintain visual consistency across section images.
  • A scroll-margin-top value applied to each section id target to offset the sticky header when anchor links are followed.
  • The go-to-top button uses position: fixed; bottom: 2rem; right: 2rem and a circular shape via border-radius: 50%.

Accessibility

All four images include meaningful alt text describing their subject matter rather than generic labels. Internal navigation links are descriptive (e.g. "Plastic Pollution", "Coral Reef Degradation"). The page uses a single <h1> with a logical descending heading structure and is readable at 200% zoom. The <main> landmark is present, and the internal nav sits within a <nav> element with an aria-label="Page sections" attribute to distinguish it from the global navigation.

🔧 Challenges & Lessons Learned

Splash Screen — Layered Animation Performance

Generating hundreds of star and ripple DOM elements in a loop initially caused noticeable paint lag on mobile. I resolved this by reducing the number of generated elements, using CSS will-change: transform, opacity to hint to the browser that these elements would animate, and replacing absolute pixel positions with percentage-based coordinates so the particles filled the viewport correctly at all screen sizes. This taught me that programmatically generated DOM elements must be treated with the same performance care as hand-written HTML.

AIS — Background Crossfade Without a Flash

My first attempt at the background image swap produced a jarring white flash when the src changed before the new image had loaded. I solved this by pre-loading all three background images into hidden <img> elements on page load, so the browser had them cached before the user could trigger a level change. The fade transition (opacity 0 → swap src → opacity 1) then worked cleanly with no flash. This was a meaningful lesson about the difference between loading and caching.

AIS — Impact Level Thresholds

Choosing fair point thresholds required testing every possible selection combination. With total points of 17 across 6 cards, I settled on Low = 0–4, Medium = 5–10, High = 11–17. This distributes the levels meaningfully: a user must commit to at least three substantive actions (≥ 11 pts) to reach "High" — which reflects the real-world effort required for meaningful ocean protection.

General — Validation Errors

Early validation runs flagged duplicate id values on the AIS page where I had accidentally copy-pasted a card template and forgotten to update the id attribute. I adopted a convention of validating after every major HTML change rather than only at the end of development, which caught errors while they were still easy to fix.

♿ Accessibility Considerations

Accessibility was considered as a design constraint from the start rather than a retrofit. Across all three pages I implemented the following practices:

  • Semantic HTML — landmark elements (<header>, <main>, <footer>, <nav>) and content elements (<section>, <h1>– <h3>) give screen readers a navigable document structure.
  • Alternative text — every <img> has an alt attribute whose value describes the image content meaningfully. Decorative-only elements use alt="" and aria-hidden="true".
  • Keyboard navigation — interactive elements (cards, buttons, skip link) are native HTML elements or carry appropriate ARIA roles, making them reachable via the Tab key without custom focus-management code.
  • Colour contrast — text colours were chosen against their backgrounds to maintain at least a 4.5:1 contrast ratio for body copy (white/light text on deep ocean backgrounds), and 3:1 for large display text, meeting WCAG 2.1 AA guidelines.
  • ARIA roles on interactive components — AIS action cards use role="checkbox"; the card grid container uses role="group"; the score panel uses role="region" so assistive technologies can identify it as a live, updating region.
  • Skip button — on the Splash Screen a visible "Skip Intro" button allows users who cannot or do not wish to wait for the countdown to proceed immediately, supporting users with vestibular sensitivities triggered by long animations.

⚖️ Compliance with JANET Regulations

All pages developed for this coursework are intended to comply with JANET regulations governing the publication of web content on UK academic networks. The following principles were followed:

  • Content appropriateness — all written content is educational, factual, and directly related to the UN Sustainable Development Goal 14. No harmful, offensive, or discriminatory material is included.
  • Intellectual property and attribution — all images used are sourced from royalty-free providers (iStockPhoto) or created specifically for this project. External resources are referenced in the References section below.
  • Academic integrity — all written content and code is original work produced by me for this coursework. No templates downloaded from the internet were used. AI-assisted content was not submitted as my own original writing.
  • Privacy — no personal data is collected or stored by any page I implemented. The profile prompt system on this website stores data only in session-level JavaScript variables and never transmits it to a server.
  • Responsible use of external services — Google Fonts is the only third-party service loaded by my pages. Users in restrictive network environments may find fonts fall back gracefully to the declared serif / sans-serif generic families.
