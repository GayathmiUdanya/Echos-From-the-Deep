Feedback Page

Technical Description

HTML Technical Description

  • <html lang="en"> declares the document language so screen readers pronounce the content correctly.
  • <meta charset="UTF-8"> sets the character encoding to support a wide range of characters and symbols.
  • <meta name="viewport"> makes the page responsive by matching the layout width to the device screen at a 1:1 zoom scale.
  • <link rel="stylesheet"> is used four times — once for Google Fonts loading Cinzel, Playfair Display, JetBrains Mono, and Inter, once for the global style.css, and once for the page-specific feedback.css.
  • <img class="scene-bg"> places the background image directly in the body so it can be positioned and layered using CSS rather than being set as a CSS background property.
  • onerror="this.style.display='none'" hides the background image element if it fails to load, so the broken image icon does not appear to the user.
  • class="active" is applied to the Feedback nav link to visually indicate the current page to the user.
  • <div class="side-nav"> provides an internal navigation panel with anchor links that jump to the Programs, Reviews, and Feedback sections of the page, allowing users to skip straight to the part they need.
  • id="programSection", id="reviewSection", and id="feedbackSection" are placed on each major section so the side nav anchor links have targets to scroll to.
  • <em> inside the hero heading wraps Our Mission. — beyond just making it italic visually, it carries semantic emphasis so screen readers stress that text when reading aloud.
  • <select> with <option> elements is used for the Sort By dropdown, giving users a controlled set of choices rather than a free text input.
  • aria-label="Sort programs" is added to the sort dropdown since it has no visible <label> element paired with it, giving screen readers a meaningful description of its purpose.
  • <div class="card-grid"> contains the six program cards, each built with a <div class="card"> holding an image, heading, description, and two action buttons.
  • <button class="btn-lm"> and <button class="btn-join"> use proper <button> tags rather than styled divs, making them naturally focusable and announced correctly by screen readers.
  • <div class="review-layout"> holds the six review cards, each using a <div class="review-card"> with a heading, review text, <hr> divider, and a footer showing the reviewer name, date, and score badge.
  • <hr> inside each review card acts as a visual divider between the review text and the reviewer details footer.
  • <span class="reviewer-name"> and <span class="score-badge"> use inline <span> tags to style small pieces of text — the reviewer name and score — without breaking the surrounding layout.
  • <form id="feedbackForm" novalidate> wraps the feedback form and novalidate disables browser default validation so JavaScript handles it instead, giving more control over error messages.
  • <fieldset> is used twice — once for Personal Details and once for Feedback Details — to group related form fields together, making the form easier to read and navigate.
  • <legend> gives each fieldset a visible title that screen readers announce when the user enters that group of fields.
  • <label for="fullname"> and equivalent labels are paired with every input using the for attribute, linking them so clicking the label focuses the correct field.
  • input type="text", type="email", type="tel", and type="date" use specific input types to trigger appropriate keyboards on mobile and provide context about the expected data to the browser and screen readers.
  • <span class="error" id="fullname-error"> sits beside each input so JavaScript can inject error messages directly next to the relevant field, making it clear to the user which field has an issue.
  • maxlength="300" on the comment textarea limits input to 300 characters, paired with a live <span id="char-count"> counter so users can see how much space remains.
  • <button type="submit"> and <button type="reset"> use proper semantic button types so the form submits and resets correctly, and both are naturally keyboard accessible.
  • <div class="success-message"> is hidden by default and shown by JavaScript after a successful form submission to confirm to the user that their feedback was received.
  • <script src="scripts/feedback.js"> is placed at the bottom of the body so the HTML loads fully before the JavaScript runs, avoiding issues with scripts trying to access elements that have not yet been rendered.

CSS Technical Description

  • position: fixed on .scene-bg keeps the background image stationary while the user scrolls, creating a parallax-like effect.
  • inset: 0 stretches the background image to cover all four edges of the viewport without needing separate top, right, bottom, and left values.
  • opacity: 0.55 makes the background semi-transparent so the content and cards remain readable over it.
  • z-index is used to layer elements correctly — the background sits at 0, the main content at 1, and the side nav at 10 so it always appears above other content.
  • position: absolute on .side-nav places it at a fixed position within the hero section, using top and right values to anchor it to the top right corner.
  • backdrop-filter: blur(14px) on .side-nav creates a frosted glass effect behind the navigation panel, letting the background show through while keeping the links readable.
  • backdrop-filter: blur(28px) on .glass-panel applies a stronger frosted glass effect to each major section container, giving the page a layered depth.
  • background: rgba(3, 13, 26, 0.85) on .glass-panel uses a semi-transparent dark fill so the background image is still slightly visible through each panel.
  • .section-label::after uses content: '' with flex: 1 and a height: 1px border to draw a thin decorative line that stretches to fill the remaining space after the section heading.
  • overflow-y: scroll on .container-grid makes the program cards section independently scrollable, keeping the page layout contained rather than letting the cards push the page length excessively.
  • display: grid with grid-template-columns: repeat(2, 1fr) on .card-grid arranges the program cards in a two-column layout that distributes space evenly between cards.
  • display: grid with grid-template-columns: repeat(3, 1fr) on .review-layout arranges the review cards in a three-column layout.
  • object-fit: cover on .card img ensures program card images fill their container without stretching or distorting regardless of the original image dimensions.
  • appearance: none on .sort-select removes the default browser dropdown arrow so custom styles can be applied consistently across browsers.
  • box-sizing: border-box on all inputs, selects, and textareas prevents them from overflowing their container when padding is added.
  • resize: vertical on textarea restricts resizing to the vertical direction only, so users cannot drag the textarea horizontally and break the form layout.
  • transition on .btn-lm, .btn-join, and the sort select smoothly animates the glow and scale effects when the user hovers over interactive elements.
  • input:focus, select:focus, and textarea:focus apply a purple border and box shadow to highlight the currently active form field, giving users a clear visual indicator of where they are in the form.
  • input::placeholder and textarea::placeholder are styled with a muted colour #4a6080 to make placeholder hint text visible but clearly distinct from actual user input.
  • button[type="submit"] and button[type="reset"] share the same style block so both buttons are consistent in size, colour, and hover behaviour without duplicating CSS rules.
  • .error is styled in red #ff6b6b and set to display: block so error messages appear on their own line directly beneath the relevant field.
  • .success-message is set to display: none by default and is shown by JavaScript after submission, confirming to the user that their feedback was received.
  • #char-count uses float: right to push the character counter to the right side of the comment label, keeping it visually associated with the field without disrupting the label text.

Accessibility

  • <html lang="en"> declares the document language so screen readers pronounce the content correctly and apply appropriate pronunciation rules.
  • <em> on the hero heading wraps "Our Mission", providing semantic emphasis so screen readers place stress on that text rather than just displaying it as italic.
  • alt="Ocean background" describes the background image for screen readers, though it could be empty (alt="") since the image is decorative.
  • onerror="this.style.display='none'" hides the background image if it fails to load, preventing a broken image icon from appearing.
  • aria-label="Sort programs" gives the dropdown a meaningful description for screen readers since there is no visible label.
  • id="programSection", id="reviewSection", and id="feedbackSection" act as anchor targets, allowing keyboard users to jump directly between sections.
  • <button class="btn-lm"> and <button class="btn-join"> use proper button elements, making them keyboard-accessible and correctly announced by screen readers.
  • <fieldset> and <legend> group related form fields and provide context, which screen readers announce when entering the group.
  • <label for="fullname"> (and similar labels) are linked to inputs, so clicking the label focuses the correct field and improves accessibility.
  • placeholder text (e.g., "Senilka Perera", "077 123 4567") guides users on what to enter and the expected format.
  • input type="email", type="tel", and type="date" provide appropriate input methods and context for both mobile devices and screen readers.
  • <span class="error"> is placed next to each input so validation messages can appear beside the relevant field.
  • maxlength="300" limits textarea input, while <span id="char-count"> provides a live character counter.
  • novalidate disables default browser validation, allowing custom JavaScript validation for consistent messaging.
  • <button type="submit"> and <button type="reset"> ensure correct form behavior and accessibility without extra scripting.
  • input:focus, select:focus, and textarea:focus styles provide a clear visual focus indicator for keyboard users.
  • <a href="#" aria-label="Back to top">↑</a> uses an aria-label to give meaning to the arrow symbol for screen readers.
  • <header>, <nav>, <main>, <form>, and <footer> act as semantic landmarks for easier navigation.
  • High contrast colours such as #e8f4f8 and #d0dce8 against #0a1a2a improve readability for users with low vision.

Technical Description

HTML Technical Description

  • <meta charset="UTF-8"> sets the character encoding to support a wide range of characters and symbols.
  • <meta name="viewport"> makes the page responsive by matching the layout width to the device screen at a 1:1 zoom scale.
  • <link rel="stylesheet"> is used three times, for Google Fonts, the global style.css, and the page-specific team.css.
  • <img class="scene-bg"> places the background image directly in the body so it can be positioned and layered using CSS, rather than being set as a CSS background property.
  • onerror="this.style.display='none'" hides the background image element if it fails to load, so the broken image icon does not appear.
  • <nav> wraps the navigation links and logo, grouping them as a landmark so screen readers can jump to it directly.
  • class="active" is applied to the Team page link in the <nav> to visually indicate the current page.
  • <section class="pageup"> contains the hero area at the top of the page, grouping the heading, content divider line, and tagline as a themed block.
  • <article class="student"> wraps each team member card as each profile is a self-contained, independent piece of content, more semantic than a plain <div>.
  • <div class="details"> groups the label-value rows inside each card and is hidden by default, only showing on hover or focus.
  • <div class="value-group"> wraps multiple values under one label, such as listing more than one page or contribution per student.
  • <a href="#" aria-label="Back to top"> provides a scroll-to-top button with a screen-reader-friendly label since the ↑ symbol has no readable text on its own.
  • <footer> contains page editor links, validation links, and the student's details, clearly separating it from the main content.

CSS Technical Description

  • position: fixed on .scene-bg keeps the background image stationary while the user scrolls, creating a parallax-like effect meaning the background moves slower than the content on top as you scroll, creating a sense of depth.
  • inset: 0 stretches the background image to cover all four edges of the viewport without needing separate top, right, bottom, and left properties.
  • opacity: 0.55 makes the background semi-transparent so the text and cards remain readable over it.
  • z-index is used to layer elements — the background sits at 0, the main content at 1, and hovered cards at 10 so they appear above neighbouring cards.
  • object-fit: cover on .student img ensures team member photos fill their frame without stretching or distorting regardless of the original image dimensions.
  • .team-members uses display: flex with flex-wrap: wrap to arrange cards in a row, automatically wrapping onto the next line on smaller screens.
  • align-items: flex-start on .team-members prevents cards from stretching to match the tallest card in the row, keeping each card at its natural height.
  • transition: all 0.3s ease on .student animates the card expansion smoothly when the user hovers over it.
  • .student:hover increases the card width from 310px to 400px to make room for the expanded details.
  • .details is set to display: none by default and changes to display: block on :hover and :focus so the profile information only appears when the user interacts with the card.
  • min-width: 150px on .label combined with flex-shrink: 0 keeps all labels a consistent width so the detail rows stay aligned across every card.
  • .btn-role uses border-radius: 20px to give the role badge a pill shape, and its transition property smoothly animates the glow and scale effect on hover.
  • box-shadow: 0 0 20px rgba(125, 211, 252, 0.3) on .student:hover img adds a soft blue glow around the photo to give visual feedback on interaction.

Accessibility

  • <html lang="en"> declares the document language so screen readers pronounce the content correctly and apply the right accent and pronunciation rules.
  • <em> on the hero heading wraps Our Story. Beyond just making it italic visually, it carries semantic emphasis so screen readers will stress that text when reading aloud, giving it more meaning than CSS italics alone.
  • alt="Image of the team member, Kulith Silva" and equivalent alt text on every team member photo describes who is in the image for users who cannot see it, so screen readers can communicate the content meaningfully.
  • alt="Ocean background" on the background image describes the decorative image to screen readers, though it could also be given an empty alt="" since it is purely decorative and does not add informational value.
  • onerror="this.style.display='none'" hides the background image if it fails to load, so the broken image icon does not appear and the page still displays cleanly for all users.
  • tabindex="0" is added to each <article class="student"> so keyboard users can tab through and focus each card without needing a mouse, which is important for users who rely on keyboard navigation.
  • :focus is included alongside :hover in the CSS rules that reveal .details, ensuring that the profile information appears for keyboard users as well as mouse users.
  • <a href="#top" aria-label="Back to top">↑</a> — the visible content is just an arrow symbol which a screen reader cannot meaningfully describe, so aria-label="Back to top" overrides what the screen reader announces, replacing the symbol with a clear text description so visually impaired users understand the purpose of the link.
  • Semantic elements — <header>, <nav>, <main>, <article>, <footer> — act as landmarks that screen readers use to jump between sections of the page quickly.
  • class="active" on the Team nav link gives a visual indicator of the current page, helping sighted users understand where they are in the site.
  • High contrast text colours such as #e8f4f8 and #d0dce8 against the dark #0a1a2a background improve readability for users with low vision.

Challenges and Lessons Learned

  • Card hover interaction required combining transition with visibility techniques, since display: none cannot be animated directly in CSS.
  • :focus was added alongside :hover to ensure the card detail reveal works for both keyboard and mouse users, improving accessibility.
  • z-index management required careful adjustment — setting the hovered card to z-index: 10 ensures it appears above neighbouring cards.
  • <fieldset> groups were split into personal details and feedback details to create clear semantic and visual separation in the form.
  • JavaScript character counter updates on every keystroke and includes reset handling to ensure it returns to the default state when the form is cleared.
  • appearance: none was used on the dropdown to remove the default browser styling, allowing consistent custom design across browsers.
  • overflow-y: scroll with a fixed height creates a contained scrollable section for program cards, requiring careful height tuning for usability.
  • novalidate enabled custom JavaScript validation, requiring individual validation logic and error handling for each input field.
  • Separate CSS files (style.css and feedback.css/team.css) were used to organise styles, requiring careful management to avoid conflicts.
  • position: absolute on the side navigation depends on a parent with position: relative, ensuring correct alignment within the hero section.
  • position: fixed with z-index layering keeps the background image behind content while remaining stationary during scrolling.
  • Consistent design system using shared colours and fonts maintained a unified theme while allowing layout differences between pages.

Compliance

  • <!DOCTYPE html> and lang="en" are included on both pages, ensuring proper HTML5 structure and correct interpretation by browsers and screen readers.
  • W3C HTML Validator was used to check both pages for structural errors, missing tags, and incorrect nesting before submission.
  • W3C CSS Validator was used to validate style.css, feedback.css, and team.css, ensuring no invalid properties or syntax errors.
  • alt attributes are applied to all images, and semantic HTML elements are used for buttons, links, and inputs to meet accessibility standards.
  • Google Gemini was used to generate images, and Google Fonts are loaded via their official API under an open licence, avoiding copyright issues.
  • HTTPS is used for all external resources, ensuring secure loading and preventing mixed content warnings.
  • No data storage is implemented in the feedback form, aligning with data minimisation principles as no user input is saved or transmitted.
  • novalidate ensures all validation is handled client-side with JavaScript, meaning no data is sent to external systems.
  • Appropriate content is maintained across both pages, with no offensive or misleading material, complying with acceptable use standards.
  • Responsive design is implemented using flex-wrap: wrap on the team page and max-width with margin: auto on the feedback page to ensure usability across devices.
