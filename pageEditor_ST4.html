Profile Page

Technical Description

HTML Technical Description

  • <div id="sample-data-container"> holds dynamic profile cards
  • <div id="profileBuilder"> contains the interactive profile builder

CSS Technical Description

  • background-attachment: fixed creates a parallax effect with a static background
  • #sample-data-container uses CSS Grid (repeat(3, 1fr)) for a 3-column layout that distributes profile cards evenly
  • .sample-data:hover uses transform: translateY(-10px) and box-shadow to create a lift effect for interactive feedback
  • .country and .role use color-coded styles for quick visual distinction
  • #profileBuilder is initially display: none and toggled to display: flex via JavaScript
  • .profile-photo uses object-fit: cover for consistent image sizing
  • Media queries (1024px, 768px, 480px) ensure responsive layout across devices

JavaScript Technical Description

  • profile stores the current profile data
  • sampleProfiles is an array of pre-filled profiles
  • renderSampleData() clears the container and displays profiles, skipping empty fields
  • createCreateButton() adds a "Create New Profile" button that triggers createProfile()
  • saveProfile() saves a profile with a random photo, replaces skipped fields, updates sampleProfiles, resets the builder, and re-renders profiles
  • clearProfile() resets fields to "Not Added Yet" and resets the progress bar after confirmation
  • createProfile() displays the builder with steps, fields, progress bar, and Save button
  • step1() collects basic info (name, age, country, role)
  • step2() collects interests (issue, animal, activity)
  • step3() collects goals and actions (goal, volunteer, awareness)
  • updateProgress() calculates completion and updates the progress bar
  • renderProfile() updates displayed fields, leaving blanks if empty

Accessibility

  • lang="en" on the <html> tag helps screen readers use correct pronunciation
  • <header>, <nav>, <main>, <section>, and <footer> act as semantic landmarks for easy navigation
  • The active navigation link uses class="active" for clear visual identification
  • aria-label="Back to top" provides a meaningful label for the ↑ anchor link
  • alt attributes on profile images describe the person for assistive technologies
  • <button> elements are used for actions, ensuring keyboard accessibility and proper screen reader support
  • prompt() and alert() guide users and enforce required input
  • High contrast between #e8f4f8 text and #081B2B backgrounds improves readability
  • Media queries ensure responsiveness for mobile and screen magnification users
  • Google Fonts display=swap prevents invisible text during font loading

Technical Description

HTML Technical Description

  • viewBox allows the diagram to scale proportionally across all screen sizes
  • Two SVGs (.desktop-map and .mobile-map) are created instead of making one responsive
  • <g> groups SVG elements together
  • <a> tags make nodes functional with hyperlinks
  • tabindex="0" enables keyboard navigation
  • <title> inside each SVG <a> provides accessible descriptions
  • <defs> stores reusable elements like <marker> (arrowheads) and <linearGradient> (fills)
  • <marker orient="auto"> adds arrowheads to lines
  • <rect rx="10"> creates rounded node boxes
  • <line> draws connections between nodes
  • <circle> shows decorative junction points
  • <text> elements display titles and subtitles with hierarchy

CSS Technical Description

  • background-attachment: fixed creates a parallax effect
  • .sitemap-wrapper centers the diagram with a dark semi-transparent panel and teal border
  • .box-rect uses smooth transition for hover animations
  • .node-group:hover ensures all node types respond consistently
  • .root-rect, .home-rect, .active-rect use distinct fills and strokes; active uses dashed stroke
  • text-anchor: middle centers labels in nodes
  • .hero_title uses clamp() for consistent font size across screens
  • .svg-link:focus adds a visible teal outline for keyboard focus
  • .desktop-map and .mobile-map toggle via media queries for responsive layouts

Accessibility

  • tabindex="0" makes SVG links keyboard-focusable
  • <title> inside SVG links provides screen reader labels
  • .svg-link:focus adds a visible teal focus outline
  • Separate desktop and mobile SVGs improve readability on all screens
  • Decorative elements (e.g., fixed background) don’t affect screen readers
  • Active link + dashed node give dual visual page indicators
  • High-contrast colors improve readability for low vision users
  • lang="en" ensures correct screen reader pronunciation
  • Semantic <header>, <main>, <footer> enable easy navigation

HTML Technical Description

  • <!DOCTYPE html> and <html lang="en"> define the document as HTML5 and set the language for accessibility and correct interpretation.
  • <meta charset="UTF-8"> ensures support for a wide range of characters and symbols.
  • <meta name="viewport"> enables responsive design by matching the layout to the device width.
  • <link rel="stylesheet"> imports external CSS files and Google Fonts to style the page.
  • <header> and <nav> structure the navigation bar, improving usability and accessibility.
  • id="quickJump" acts as a navigation landmark with an aria-label to ensure screen readers identify it as a functional section for jumping between content.
  • id="qjPill" serves as the main container for the navigation items, likely styled as a floating or sticky horizontal "pill" bar.
  • class="qj-item" creates internal page links using href anchors (like #act1) to scroll the user to specific sections without a page reload.
  • class="active" and aria-current="true" are used on the first link to visually and programmatically mark the user's starting location in the document.
  • class="qj-connector" provides a structural element used in CSS to draw connecting lines between the navigation points, creating a "progress tracker" look.
  • class="qj-dot" functions as a decorative or functional bullet point within each link to give the menu a modern, minimalist aesthetic.
  • data-target attributes store the ID of the destination section, which is typically used by a JavaScript scroll-spy to highlight the correct link as the user scrolls.
  • <main> wraps the primary content, helping screen readers identify the main section of the page.
  • <section> elements divide the page into logical content areas such as hero, content cards, and handoff.
  • id attributes (e.g., #top, #act3) are used for internal navigation and anchor linking.
  • class attributes are used to apply consistent styling and layout through CSS.
  • data-* attributes (e.g., data-bg, data-ch) store custom data used by JavaScript for dynamic behaviour.
  • <img> elements include alt text for accessibility and onerror to hide images if they fail to load.
  • aria-hidden="true" is used to hide decorative elements from screen readers.
  • <a> elements provide navigation between pages and within the page using anchor links.
  • <script src="..."> links an external JavaScript file, separating behaviour from structure.
  • <footer> contains additional navigation and student details, placed at the end of the page.

CSS Technical Description

  • body sets a dark background colour, creating the base theme of the page.
  • .sonar uses position: absolute, border-radius: 50%, and transform to create circular ripple elements.
  • @keyframes sonarRing defines the ripple animation using transform and opacity to simulate expanding waves.
  • .sonar.fire, .fire2, and .fire3 apply staggered animations using delays for a layered ripple effect.
  • #sonarpart uses position: fixed and pointer-events: none so the animation stays centred and does not block user interaction.
  • .bg uses position: fixed and opacity transitions to create smooth background image changes.
  • .bg.active switches visibility by increasing opacity and z-index, controlling which background is shown.
  • .bimg uses object-fit: cover to ensure images fill the screen without distortion.
  • .bg::after applies gradient overlays using pseudo-elements to improve text readability over images.
  • .chapters uses Flexbox (display: flex) to centre content both vertically and horizontally.
  • clamp() is used for responsive font sizes, adjusting text smoothly across different screen sizes.
  • .contentcon uses backdrop-filter: blur() and semi-transparent backgrounds to create a glassmorphism effect.
  • .contentcon.visible uses opacity and transform transitions to animate content appearing on scroll.
  • z-index is used throughout (e.g., background = 0, content = 10) to control layering of elements correctly.
  • @keyframes scrollDrop animates the scroll indicator line using transform and opacity for a looping effect.
  • #quickJump is fixed to the right side of the viewport, vertically centered using transform: translateY(-50%)
  • #qjPill is the container, a frosted glass pill using backdrop-filter: blur, dark semi-transparent background, and a subtle sky-blue border
  • .qj-item is each nav dot row, flexbox-aligned, with a soft hover background highlight
  • .qj-label is a tooltip that appears to the left of each dot, hidden by default (opacity: 0, transparent color), revealed on hover, focus, or when .active
  • .qj-dot is the circular indicator, small 6px dot with a sky-blue tint; scales up on hover and glows on active
  • .qj-item.active .qj-dot applies a cyan glow via box-shadow and scales the dot to 1.4x
  • .qj-dot::after creates a pulse ring, an expanding border that animates outward using @keyframes qjPulse only when the item is active
  • .qj-connector is a thin 1px vertical line between dots, acting as a visual divider

JavaScript Technical Description

  • document.getElementById() is used to select specific elements such as the scroll bar and sonar rings.
  • document.querySelectorAll() selects multiple elements (e.g., sections with data-bg) and converts them into an array using Array.from().
  • reduce() is used to create an object mapping background IDs to their corresponding DOM elements for efficient access.
  • switchBg() function controls background transitions by adding and removing the active class.
  • classList.add() and classList.remove() dynamically update CSS classes to change styles and trigger animations.
  • setTimeout() is used to delay actions such as resetting z-index and controlling animation timing.
  • window.addEventListener('scroll') listens for scrolling to update the progress bar and trigger effects.
  • window.pageYOffset and document height calculations are used to determine scroll progress.
  • getBoundingClientRect() calculates the position of sections to detect which section is closest to the viewport centre.
  • dataset (e.g., dataset.bg) accesses custom HTML data attributes to control background switching.
  • IntersectionObserver detects when elements enter the viewport and adds a visible class for animations.
  • addEventListener('load') ensures initial functions run only after the page fully loads.
  • Tracks which section is closest to 45% down the viewport
  • qjItems = all nav links in #quickJump; qjTargets = their data-target section IDs
  • On each call, computes a midpoint (winMid) at 45% of the viewport
  • Loops through all target sections, finds the one whose center is closest to winMid
  • Toggles the active class on the matching nav item, removes it from the rest
  • scrollY is passed in by the caller, usually from a scroll event

Challenges and Lessons Learned

  • Building a multistep profile builder with real time updates seemed challenging at first but became manageable with careful planning.
  • The SVG sitemap had to be built twice, once for desktop and once for mobile—because fixed coordinates prevented responsive scaling.
  • Making the sitemap keyboard accessible required adding extra attributes to each SVG node, which was initially overlooked.
  • Keeping CSS organised across separate files for each page required discipline to avoid style conflicts.
  • Maintaining a consistent visual theme across all pages was an important part of the process.

Compliance

  • All pages include a valid declaration and lang attribute, ensuring properly structured HTML5 documents.
  • Both pages were validated using the W3C HTML Validator to check for structural errors, unclosed tags, and incorrect nesting.
  • CSS was validated using the W3C CSS Validator to confirm no invalid properties or syntax errors exist.
  • Images include alt attributes and interactive elements use semantic tags, meeting basic accessibility requirements.
  • All images are generated using Google Gemini and Google Fonts are loaded via their official API under open licence, ensuring no copyright violations.
  • External resources load over HTTPS, complying with secure resource loading requirements.
  • No personal data is stored beyond the current session, aligning with data minimisation principles.
  • Pages contain no offensive, discriminatory, or misleading content, complying with Janet's acceptable use standards.
  • Responsive design ensures pages are accessible across a range of devices and screen sizes.
