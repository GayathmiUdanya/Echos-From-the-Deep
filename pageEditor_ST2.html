Technical Description

HTML Technical Description

  • <!DOCTYPE html> and <html lang="en"> define the document as HTML5 and set the language for accessibility and correct interpretation.
  • <meta charset="UTF-8"> ensures support for a wide range of characters and symbols.
  • <meta name="viewport"> enables responsive design by matching the layout to the device width.
  • <link rel="stylesheet"> imports external CSS files and Google Fonts to style the page.
  • <header> and <nav> structure the navigation bar, improving usability and accessibility.
  • <main> wraps the primary content, helping screen readers identify the main section of the page.
  • <section> elements divide the page into logical content areas such as hero, content cards, and handoff.
  • id attributes (e.g., #top, #act3) are used for internal navigation and anchor linking.
  • class attributes are used to apply consistent styling and layout through CSS.
  • data-* attributes (e.g., data-bg, data-ch) store custom data used by JavaScript for dynamic behaviour.
  • <img> elements include alt text for accessibility and onerror to hide images if they fail to load.
  • aria-hidden="true" is used to hide decorative elements from screen readers.
  • <a> elements provide navigation between pages and within the page using anchor links.
  • <script src="..."> links an external JavaScript file, separating behaviour from structure.
  • <footer> contains additional navigation and student details, placed at the end of the page.

CSS Technical Description

  • body sets a dark background colour, creating the base theme of the page.
  • .sonar uses position: absolute, border-radius: 50%, and transform to create circular ripple elements.
  • @keyframes sonarRing defines the ripple animation using transform and opacity to simulate expanding waves.
  • .sonar.fire, .fire2, and .fire3 apply staggered animations using delays for a layered ripple effect.
  • #sonarpart uses position: fixed and pointer-events: none so the animation stays centred and does not block user interaction.
  • .bg uses position: fixed and opacity transitions to create smooth background image changes.
  • .bg.active switches visibility by increasing opacity and z-index, controlling which background is shown.
  • .bimg uses object-fit: cover to ensure images fill the screen without distortion.
  • .bg::after applies gradient overlays using pseudo-elements to improve text readability over images.
  • .chapters uses Flexbox (display: flex) to centre content both vertically and horizontally.
  • clamp() is used for responsive font sizes, adjusting text smoothly across different screen sizes.
  • .contentcon uses backdrop-filter: blur() and semi-transparent backgrounds to create a glassmorphism effect.
  • .contentcon.visible uses opacity and transform transitions to animate content appearing on scroll.
  • z-index is used throughout (e.g., background = 0, content = 10) to control layering of elements correctly.
  • @keyframes scrollDrop animates the scroll indicator line using transform and opacity for a looping effect.

JavaScript Technical Description

  • document.getElementById() is used to select specific elements such as the scroll bar and sonar rings.
  • document.querySelectorAll() selects multiple elements (e.g., sections with data-bg) and converts them into an array using Array.from().
  • reduce() is used to create an object mapping background IDs to their corresponding DOM elements for efficient access.
  • switchBg() function controls background transitions by adding and removing the active class.
  • classList.add() and classList.remove() dynamically update CSS classes to change styles and trigger animations.
  • setTimeout() is used to delay actions such as resetting z-index and controlling animation timing.
  • window.addEventListener('scroll') listens for scrolling to update the progress bar and trigger effects.
  • window.pageYOffset and document height calculations are used to determine scroll progress.
  • getBoundingClientRect() calculates the position of sections to detect which section is closest to the viewport centre.
  • dataset (e.g., dataset.bg) accesses custom HTML data attributes to control background switching.
  • IntersectionObserver detects when elements enter the viewport and adds a visible class for animations.
  • addEventListener('load') ensures initial functions run only after the page fully loads.

Accessibility

  • lang="en" defines the page language, helping screen readers use correct pronunciation.
  • alt attributes on images provide descriptions for visually impaired users.
  • aria-hidden="true" hides decorative elements (e.g., background images, sonar effects) from screen readers.
  • <header>, <nav>, <main>, <section>, and <footer> create a semantic structure for easier navigation.
  • aria-label (e.g., "Back to top") gives meaningful descriptions to icons or non-text elements.
  • <a> links enable keyboard navigation between sections and pages.
  • <em> and <strong> provide semantic emphasis, improving how screen readers interpret content.
  • id attributes allow users to jump to sections using anchor links, supporting keyboard navigation.

Compliance

  • All pages include a valid <!DOCTYPE html> declaration and lang attribute, ensuring properly structured HTML5 documents.
  • Both pages were validated using the W3C HTML Validator to check for structural errors, unclosed tags, and incorrect nesting.
  • CSS was validated using the W3C CSS Validator to confirm no invalid properties or syntax errors exist.
  • Images include alt attributes and interactive elements use semantic tags, meeting basic accessibility requirements.
  • All images are generated using Google Gemini and Google Fonts are loaded via their official API under open licence, ensuring no copyright violations.
  • External resources load over HTTPS, complying with secure resource loading requirements.
  • No personal data is stored beyond the current session, aligning with data minimisation principles.
  • Pages contain no offensive, discriminatory, or misleading content, complying with Janet's acceptable use standards.
  • Responsive design ensures pages are accessible across a range of devices and screen sizes.
