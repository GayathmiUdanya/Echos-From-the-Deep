Gallery Page

Technical Description

  • <nav class="nav-links"> manages the site's primary navigation and page states.
  • <div class="dashboard-container"> implements the CSS Grid system for the 3-column gallery.
  • <div class="card"> acts as a flexbox container for image assets and text metadata.
  • <div id="galleryModal"> serves as the dynamic UI overlay for expanded content.
  • <footer> holds student identification, project copyright, and administrative links.
  • :root defines the central theme palette and typography variables.
  • .scene_bg uses object-fit: cover and fixed positioning for an immersive background.
  • .card:hover applies a translateY transform to provide interactive depth.
  • @media queries handle the transition from 3-column to 1-column responsive layouts.
  • .alt-font-active forces a monospaced font override using !important priority.
  • querySelectorAll('.card') selects all gallery items to attach event listeners.
  • mouseenter / mouseleave dynamically updates border colors and positioning.
  • modal.style.display controls the visibility state of the expanded image view.
  • classList.toggle enables the "Change Font" and "Change Colour" accessibility features.
  • window.onclick detects clicks outside the modal to trigger the close logic.

Accessibility

  • <html lang="en"> defines the base language to ensure screen readers use correct pronunciation.
  • <main> and <nav> provide ARIA landmarks, allowing users to jump directly to specific sections.
  • aria-label="Back to top" provides a clear text description for the symbolic "↑" link for non-visual users.
  • <header> and <footer> group related navigation and metadata for a logical page hierarchy.
  • alt attributes on all images (e.g., "Discarded fishing net") provide critical visual context to screen reader users.
  • opacity: 0.55 on the background image maintains a high contrast ratio between the text and the scenery.
  • line-height: 1.6 in the modal text prevents crowding, making long descriptions easier for users with cognitive impairments to read.
  • cursor: pointer and :hover states give immediate visual feedback that an element is interactive.
  • btnFont toggles a monospaced font, which is often easier for users with dyslexia or reading difficulties to process.
  • btnColor switches to a high-contrast scheme, assisting users with color blindness or light sensitivity.
  • overflow-y: auto ensures that the modal remains fully scrollable for users on small screens or with high browser zoom.
  • onerror="this.style.display='none'" hides broken images to prevent screen reader confusion and maintain a clean layout.

Group Meetings and Individual Contribution Log

  • <!DOCTYPE html> and lang="en" are included on both pages, ensuring proper HTML5 structure and correct interpretation by browsers and screen readers.
  • W3C HTML Validator was used to check both pages for structural errors, missing tags, and incorrect nesting before submission.
  • W3C CSS Validator was used to validate style.css, feedback.css, and team.css, ensuring no invalid properties or syntax errors.
  • alt attributes are applied to all images, and semantic HTML elements are used for buttons, links, and inputs to meet accessibility standards.
  • Google Gemini was used to generate images, and Google Fonts are loaded via their official API under an open licence, avoiding copyright issues.
  • HTTPS is used for all external resources, ensuring secure loading and preventing mixed content warnings.
  • No data storage is implemented in the feedback form, aligning with data minimisation principles as no user input is saved or transmitted.
  • novalidate ensures all validation is handled client-side with JavaScript, meaning no data is sent to external systems.
  • Appropriate content is maintained across both pages, with no offensive or misleading material, complying with acceptable use standards.
  • Responsive design is implemented using flex-wrap: wrap on the team page and max-width with margin: auto on the feedback page to ensure usability across devices.
